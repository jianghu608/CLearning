========================================
  转专业机考 · C语言易错点速查
========================================

--- 1. 变量未初始化（致命） ---

int idx;       // 错：栈上垃圾值，写越界/打印乱码
int idx = 0;   // 对：声明即赋值

int sum;               // 错
int sum = 0;           // 对
int max = arr[0];      // 对（数组已读入的前提下）

规则：所有局部变量声明时都给初值。


--- 2. 数组/循环漏边界（致命） ---

题目说分数 0~100：
  for (j = 1; j <= 100; j++)   // 错：漏了 flag[0]
  for (j = 0; j <= 100; j++)   // 对

题目说 n 个学生（下标 0~n-1）：
  for (i = 0; i < n; i++)      // 对
  for (i = 0; i <= n; i++)     // 错：多跑一次，越界

检查要点：数组下标 0 是否被你的循环覆盖了？


--- 3. 多组数据 -> 组间空行（致命） ---

要求："每组输出之间有一个空行"

标准写法：
  int first = 1;
  while (scanf(...) != EOF) {
      if (!first) printf("\n");   // 除了第一组，前面加空行
      first = 0;
      // 处理并输出本组数据
  }

常见错误：
  x 每组末尾加 printf("\n")          // 最后多一个空行
  x 什么都不加                       // 组间没有空行


--- 4. scanf 格式匹配（经常丢分） ---

输入格式为 (3,+3) 时：
  scanf("(%d,%d)", &a, &b);   // 括号和逗号必须照写
  getchar();                   // 吃掉换行，防止下一轮卡住

常见报错场景：
  - 输入有括号但 scanf 没写括号     -> 匹配失败
  - 读完数字没 getchar() 清换行     -> 下一轮 scanf 读到 '\n' 卡死
  - 用 %d 读 %lld 范围的数据        -> 溢出


--- 5. 转义字符 ---

想输出           写
--------        --------
\               \\
"               \"
%               %%
'               \'（字符常量中）
\n              换行
\t              Tab

考题样例：输出 ~\\You're the best!\\  ～～  /  ~
  要写成 printf("~\\\\You're the best!\\\\\n");


--- 6. 逗号/空格分隔输出 ---

  for (i = 0; i < n; i++) {
      if (i > 0) printf(",");    // 第一项前无逗号
      printf("%d", arr[i]);
  }

空格分隔同理：
  if (i > 0) printf(" ");


--- 7. char 数组大小留余量 ---

题目说每行不超过 200 字符：
  char s[205];    // 对，\0 + 余量
  char s[200];    // 错，存不下 200 字 + \0

fgets 写法：
  fgets(s, sizeof(s), stdin);
  int len = strlen(s);
  if (s[len-1] == '\n') s[--len] = '\0';  // 去掉自带换行


--- 8. scanf 与 fgets 混用 ---

  scanf("%d", &n);         // 读完数字，换行符留在缓冲
  getchar();               // 一定要吃掉这个换行
  fgets(line, 205, stdin); // 否则读到空行


--- 9. 字符判断用 ctype.h ---

  #include <ctype.h>

  isalpha(c)    是否字母（'a'~'z', 'A'~'Z'）
  isdigit(c)    是否数字（'0'~'9'）
  isalnum(c)    是否字母或数字
  isspace(c)    是否空白（空格、\t、\n 等）
  toupper(c)    转大写
  tolower(c)    转小写

好处：比手写 (c >= 'a' && c <= 'z') 更安全，自动处理大写。


--- 10. EOF 判断的正确写法 ---

  while (scanf("%d", &n) != EOF)   // 对，标准写法
  while (!feof(stdin))              // 错：读完最后一个数据
                                    //  feof 才为真，会多循环一次


--- 11. 数组开大一点 ---

题目说 n <= 1000，开 arr[1005] 或 arr[1010]
题目说 n <= 100，开 arr[105]
多出来的 5~10 个元素是缓冲区，防越界。


--- 12. 平均分保留小数 ---

  double avg = (double)sum / n;    // 先转型再除
  printf("%.1f", avg);             // 保留 1 位小数

  int sum = 0;
  double avg = sum / n;            // 错：整数除法，小数被截断


--- 13. 考试检查清单 ---

写完代码后逐项检查：

[ ] 所有局部变量都初始化了？
[ ] 数组下标从 0 还是 1 开始？有没有漏 0？
[ ] for 循环条件是 i < n 还是 i <= n？
[ ] 多组数据之间的空行处理对了吗？
[ ] scanf 格式串和输入格式完全匹配？
[ ] scanf 后要 getchar() 清换行？
[ ] printf 格式符和变量类型一致（%d/%lf/%lld）？
[ ] 整数除法前有没有转 double？
[ ] 数组开得比题目要求大 5~10？
[ ] 跑过样例 + 自己想一个边界测？


--- 14. 考试时间节奏 ---

0-30min:  做送分题（前 2 题），全拿
30-60min: 做中等题
60-90min: 冲难题，拿部分分
90-120min: 检查 + 补漏

卡住 15 分钟没思路 -> 跳下一题。
样例过了不等于全对 -> 一定要想边界。


--- 15. 考场调试三板斧 ---

第一板斧：输出中间变量

结果不对，加一行 printf 看看中间值。

  // 怀疑 min 算错了，就打印它
  printf("DEBUG: flag[0]=%d, min=%d\n", flag[0], min);

看到数值的那一刻你通常就懂了。
关键：不要瞪眼猜，动手打出来。

第二板斧：注释掉复杂逻辑，验证基础

输出完全乱掉时，先把处理逻辑全注释掉，
只保留输入输出，确认读入是对的：

  while (scanf("%d", &n) != EOF) {
      getchar();
      for (int i = 0; i < n; i++) {
          fgets(line, 205, stdin);
          printf("LINE[%d]: %s\n", i, line);  // 只看读入
      }
  }

输入读对了，再逐步放开处理代码。
不要一次性面对全部复杂度。

第三板斧：逆推法（最冷静的一种）

1. 看错误输出，找到第一个不对的字符/数字
2. 反向追问：这个值是从哪个变量来的？
3. 那个变量是在哪一行赋值的？
4. 赋值时用的数据本身对不对？

以今天 E 题为例：
  看到 I后面有乱码
  -> 乱码从 word[] 来
  -> word[] 逐字母填，idx 控制位置
  -> idx 初始值是多少？
  -> int idx; 没初始化 -> 命中


--- 16. 考场检查顺序（按概率排序） ---

从高到低排查，只花 2 分钟：

  1. 变量初始化了吗？
  2. 循环条件 < 还是 <=？从 0 还是 1？
  3. 数组越界了吗？（n=1 时跑不跑得通？）
  4. scanf 格式串写对了？（括号、逗号）
  5. int/int 没转 double 丢小数了？
  6. printf 格式符和变量类型匹配？
  7. 多组数据空行处理了？


--- 17. 什么时候该放弃调试 ---

10 分钟找不到根因 -> 直接重写。

重写比调试快。重写时：
  - 用更简单的写法（冒泡比桶排序好写）
  - 变量名起长一点（word_idx 比 idx 好）
  - 写完立刻跑刚才的样例确认


--- 18. 一句话原理 ---

调试是猜谜游戏。
你的敌人不是机器，是你自己写的代码。
机器永远是对的。结果不对，一定是你哪行代码写错了。
